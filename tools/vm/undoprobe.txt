== jd's case: bold 0..3, then type, then undo ==
  the base, unbolded     text abcdef                 canundo 0  next-undo unknown  0..3 plain(m003F e0000)
  after bolding 0..3     text abcdef                 canundo 1  next-undo unknown  0..3 bold (m003F e0001)
  after typing XY        text abcdefXY               canundo 1  next-undo TYPING   0..3 bold (m003F e0001)
                         text abcdef                 canundo 1  next-undo unknown  0..3 bold (m003F e0001)
                         text abcdef                 canundo 0  next-undo unknown  0..3 plain(m003F e0000)

  A row where the text shortens is an undo of the typing.
  A row where 0..3 goes bold->plain is an undo of the style.
  Whether the style comes back at all is the answer to jd's
  report, and the ORDER is the answer to whether one step can
  hold both.

== jd's sequence: select all, bold, then type (inherits) ==
  abc, unbolded        text abc        canundo 0  next unknown  old plain(m003F e0000) new plain(m003F e0000)
  all bolded           text abc        canundo 1  next unknown  old bold (m003F e0001) new bold (m003F e0001)
  typed XY at the end  text abcXY      canundo 1  next TYPING   old bold (m003F e0001) new bold (m003F e0001)
                       text abc        canundo 1  next unknown  old bold (m003F e0001) new plain(m003F e0000)
                       text abc        canundo 0  next unknown  old plain(m003F e0000) new plain(m003F e0000)

  `old` is the original abc; `new` is the typed XY. The first
  undo taking the text back leaves `old` bold. The first undo
  taking the style back is jd's bug, on the machine.

== typed base, then arm, then type: does arming break the run? ==
  typed abc, arm, typed XY text abcXY      canundo 1  next TYPING   old plain(m003F e0000) new bold (m003F e0001)
                       text abc        canundo 1  next TYPING   old plain(m003F e0000) new plain(m003F e0000)
                       text            canundo 0  next unknown  old plain(m003F e0000) new plain(m003F e0000)

  Text "abc" after the first undo means arming BREAKS the
  typing run and they are two transactions. Empty means it does
  not and the whole typing session is one.

== the arming route, base set rather than typed ==
  typed XY             text abcXY      canundo 1  next TYPING   old plain(m003F e0000) new bold (m003F e0001)
                       text abc        canundo 0  next unknown  old plain(m003F e0000) new plain(m003F e0000)

  Arming changes no text, so if it pushes no undo step the
  count here is one lower than above and the shapes differ.
  Nothing is read between the arm and the typing: looking moves
  the selection, and moving the caret discards the armed format.

== depth: how many steps does it keep? ==
  120 formatting changes, one step each
  100 undo(s) before it would not undo further
  0..3 is now plain(m003F e0000)
  120 means it kept every step and the limit is higher.
  Fewer is the depth, and the state left behind is what the
  steps that fell off the bottom would have restored.

== reading the columns above ==

`new` is indices 3..5. After an undo shortens the text those indices no
longer exist, and riched20 answers a read past the end from the armed
insertion format rather than failing -- bob's phantom index, found the same
evening from the other side. So `new` on any row where the text is shorter
than 5 characters is NOT evidence; `old` is the column that carries the
answer there.
